The brief, and what shipped

Automate two flows on the Shiftbase demo environment: signup + onboarding up to the dashboard, and login. This is what came back.

Both flows, end to end

Signup walks the 8-step questionnaire and setup wizard to the dashboard; login handles the MFA interstitial. Interactions read as intent through the Steps API — no raw selectors in any test.

Some observations along the way

Testing a real product surfaces things. A few came up while building the happy paths, and a focused exploratory pass found more — all reproduced, none false positives. Shared constructively, for the team to weigh.

Evidence, not claims

Each observation carries a reproduction and a screen recording or screenshot. Anything that couldn’t be pinned by a portable test is written up with the reason, not forced into one.

Runnable by anyone

npm ci && npm test on a clean clone with no .env. Verified by cloning fresh; the suite provisions its own account through the real signup flow.

What the tests surfaced

Ten observations on the demo environment, each reproduced and independently re-checked. Shared as the kind of thing thorough automation is built to catch.

Highest priority · consent

Terms & Data-Processing-Agreement acceptance is enforced only in the browser

On the demo environment, POST /api/signup accepts a request with accept_conditions: false and creates a usable account — the consent checkbox the UI requires has no server-side counterpart. Worth a look because the same pattern in production would record consent that was never given. Reported rather than automated, so a regression run never repeats it against the shared environment.

QA Assessment
07 / 08

Engineering choices worth a look

The decisions a reviewer running this cold would notice.

No committed credentials

A setup project provisions an account via the real signup flow when no .env is present, so a cold clone runs green. Secrets live in .env (gitignored); an independent sweep confirmed none shipped.

Flake, root-caused not retried

The Angular questionnaire can drop clicks mid-render; every input is re-applied until it lands (verified 12× with retries off). The residual is the environment’s own gateway variability, left to configured retries.

Watchable headed runs

npm run test:headed drops to one worker and paces each action, so a reviewer can actually follow the flows rather than watch windows race.

TLS reality documented

The demo serves a private-CA cert that rolls every 24h; the suite sets ignoreHTTPSErrors and says so plainly — on a production target that setting would hide a real issue.
